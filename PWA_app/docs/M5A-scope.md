# M5A — اتصال کلاینت کمین به سرور (اسکوپ ادامه‌ی کار)

**وضعیت:** بک‌اند M5 کامل و لایو-تست‌شده است (موتور کمین، Web Push، نوتیفیکیشن، همه‌ی باگ‌بانتی‌ها).
کلاینت هنوز به سرور وصل نیست — کمین‌ها همچنان localStorage هستن.

## اسکوپ M5A (فقط کلاینت، بدون تغییر بک‌اند)

### ۱. RadarDialog → سرور
- `src/components/search/RadarDialog.tsx` در حال حاضر به API وصل نیست
- اتصال به `POST /api/kamins` (با idempotency روی `canonical_key`)
- مدیریت خطاها: slot پر، تعریف تکراری (dedupe نه ارور)، کاربر مهمان (گیت)

### ۲. درخواست دسترسی Push
- هنگام arm کردن کمین (explicit action)، درخواست permission برای Web Push
- ثبت subscription در `POST /api/push/subscriptions`
- UX فارسی و محترمانه — نه پاپ‌آپ مرورگر خشک

### ۳. صفحه‌ی /saved → سرور
- در حال حاضر از `kamin-store` (localStorage) می‌خونه
- لود کمین‌ها از `GET /api/kamins`
- نمایش `new_match_count`، `last_checked_at`، وضعیت `active/sleeping`
- اکشن‌ها: `DELETE /api/kamins/:id` (حذف دو مرحله‌ای)، `POST /api/kamins/:id/run` (اجرای دستی = شکار پولی)
- مهاجرت دیتای local موجود به سرور (یک‌بار، با تایید کاربر)

### ۴. اینباکس نوتیفیکیشن
- `GET /api/notifications` در هدر (آیکون زنگ)
- علامت خوانده‌نشده برای مچ‌های جدید کمین
- `POST /api/notifications/:id/read`

### ۵. QA تصویری
- طبق قانون نوید: بعد از هر مرحله‌ی بصری، اسکرین‌شات برای ریویو

## بیرون از اسکوپ (فازهای بعدی)
- **M5b (وب‌هوک اشتراک):** `wakeKaminsForUser` هنوز صدا زده نمی‌شه — وقتی وب‌هوک تمدید اشتراک اومد، کمین‌های sleeping بیدار می‌شن (نیاز به M6 دارد)
- **M6:** سیکل اشتراک، ایندکس ماهانه‌ی دلار، صندلی‌های الماس
- **Sync engine:** کل دیتای کاربر server-side (اسلایس جدا، طبق تصمیم قبلی)

## ترتیب پیشنهادی
1. RadarDialog → سرور (کوچک‌ترین، مستقل)
2. Push permission + subscription
3. /saved → سرور + مهاجرت local
4. اینباکس نوتیفیکیشن
5. QA تصویری هر مرحله

**تخمین:** هر مرحله یک سشن کاری. بدون تغییر بک‌اند، بدون مایگریشن جدید.
